# cPME.2 Project Notes

## What This Package Is

`cPME.2` is an R package for research on principal manifold estimation and surface registration. The package is used to fit low-dimensional parameterized manifolds or surfaces from high-dimensional data, then compare, align, evaluate, and visualize those fitted surfaces.

The main scientific workflow is:

1. Estimate a principal manifold/surface from point-cloud or voxel-derived surface data.
2. Represent the fitted surface as a smooth embedding from a low-dimensional parameter domain, usually 2D, into a higher-dimensional space, often 3D.
3. Register one fitted surface to another through reparameterization maps on the parameter domain.
4. Use SIME/cPME-style workflows to compare subject/template surfaces, evaluate fit quality, and estimate surface or volume-related quantities.

This is active research code organized as an R package. Some metadata in `DESCRIPTION` is still template-like, but the source tree already follows normal R package conventions.

## Package Structure

- `DESCRIPTION`: Package metadata, dependencies, GitHub URL, R version requirement, and Rcpp linking information.
- `NAMESPACE`: Generated by roxygen2. Do not edit manually.
- `R/`: Main R source code for PME, SIME, registration, simulation, preprocessing, visualization, and evaluation.
- `src/`: C++/Rcpp source code for computational helpers.
- `man/`: Generated R documentation files.
- `R-old/`: Older implementations kept for reference. Do not treat this as the active package code unless explicitly comparing legacy behavior.
- `renv/`: Project environment support files.
- `cPME.2.Rproj`: RStudio project file. It can remain in the repository; Positron can open the folder directly.
- `.git/`: Git repository metadata. GitHub connection is controlled here, not by RStudio or Positron.

At the time this note was written, there were no top-level `tests/`, `vignettes/`, `.qmd`, or `.Rmd` files.

## Main R Modules

### Principal Manifold Estimation

- `R/pme.R`: Main `pme()` function and PME object helpers. This is the best starting point for understanding the core estimation workflow.
- `R/pme_helpers.R`: Spline fitting, smoothing kernels, projection, parameter updates, SSD/MSD calculations, embedding factories, gradient factories, plotting, and scaling helpers.
- `R/hdmde.R`: High-dimensional mixture/density estimation helpers used for initialization and clustering/data reduction.

### Surface Registration

- `R/registration_class.R`: Current `Registration` R6 class. This is the active registration implementation. It handles basis construction, grid evaluation, iterative reparameterization, safe step acceptance, backtracking, and state history.
- `R/registration_helpers.R`: Helper functions used by the current registration class.
- `R/registration_class_legacy.R` and `R/registration_legacy_helpers.R`: Older registration implementation. Useful for comparison, but not the main path.
- `R/PMERegistrationCycle.R`: High-level R6 workflow that alternates PME fitting, registration, and PME refitting across cycles.

### SIME And Evaluation

- `R/SIME.R`: SIME workflow with anchor penalty and lambda screening, plus selection helpers.
- `R/Evaluation_Utils.R`: Fit evaluation utilities, manifold/correspondence MSD calculations, surface orientation tools, and partitioned surface-volume estimation.
- `R/surface_preprocessing.R`: Tools for extracting surface voxels, estimating midplanes, and partitioning surfaces.

### Simulation, Basis, And Visualization

- `R/basis_constructions.R`: Basis functions and basis grids used in registration.
- `R/simulation_helpers.R`: UV grids, synthetic surface generation, bump fields, and surface-combination helpers.
- `R/visualization_helpers.R`: Plotting and visualization helpers.
- `R/pme_orientation_check.R`: Orientation consistency checks for PME initializations.

## Rcpp / C++ Code

- `src/helpers.cpp`: RcppArmadillo/BH-backed numerical code. It includes Euclidean distance/norm helpers, log-space arithmetic, smoothing kernels, eta-kernel calculations, nearest-point initialization helpers, mixture-weight calculations, and weighted spline solving.
- `R/RcppExports.R` and `src/RcppExports.cpp`: Generated files. Do not edit manually.
- `src/Makevars` and `src/Makevars.win`: Native compilation settings using OpenMP plus BLAS/LAPACK/Fortran libraries.

If a C++ function with `// [[Rcpp::export]]` is added, removed, renamed, or has its signature changed, regenerate wrappers with:

```r
Rcpp::compileAttributes()
devtools::document()
```

## Recommended Development Workflow

From the package root in Positron, RStudio, or an R terminal:

```r
devtools::load_all()
```

Use this first during interactive development. It loads the package without installing it.

```r
devtools::document()
```

Use this after editing roxygen comments or exported functions. It regenerates `NAMESPACE` and files in `man/`.

```r
Rcpp::compileAttributes()
devtools::document()
```

Use this after changing exported Rcpp functions.

```r
devtools::install(args = c("--no-multiarch", "--with-keep.source"))
```

Use this to install and compile the package locally.

```r
devtools::check()
```

Use this before committing important package changes.

`devtools::test()` can be used once a `tests/` directory exists. At present, there may be no tests to run.

## Guidance For Future Coding Agents

- Start by reading `R/pme.R`, `R/pme_helpers.R`, `R/registration_class.R`, and `R/PMERegistrationCycle.R` before changing algorithm behavior.
- Keep edits small and tied to a specific workflow: PME, SIME, registration, preprocessing, evaluation, visualization, or Rcpp helpers.
- Do not edit generated files by hand: `NAMESPACE`, `man/*.Rd`, `R/RcppExports.R`, or `src/RcppExports.cpp`.
- Do not remove `R-old/` unless explicitly instructed. It is useful for historical comparison.
- Do not change Git remotes, branches, or Dropbox/project paths unless explicitly asked.
- Avoid committing local/session/build artifacts such as `.Rhistory`, `.RData`, `.Rproj.user/`, `.dll`, `.o`, or temporary check folders.
- For numerical changes, add or run focused examples/tests when possible, because small changes can affect downstream surface registration and PME fitting behavior.
- Preserve public function names and exported APIs unless the user explicitly wants an API redesign.
